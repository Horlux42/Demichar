### **Описание ER-диаграммы базы данных**
**Над диаграммой работал:**  **Приходько Н.** - составление и разработка диаграммы.
### **Сущности и их атрибуты**
## **1. User (Пользователь)**

- **user_id** (PK) — уникальный идентификатор пользователя
- email — электронная почта пользователя
- password_hash — хэш пароля
- display_name — отображаемое имя
- created_at — дата регистрации
## **2. Sheet (Лист персонажа)**

- **sheet_id** (PK) — уникальный идентификатор листа
- **owner_user_id** (FK) — ссылка на пользователя-владельца
- name — название листа
- description — описание листа
- canvas_width — ширина рабочей области
- canvas_height — высота рабочей области
- created_at — дата создания
- updated_at — дата последнего изменения
## **3. SheetVersion (Версия листа)**

- **version_id** (PK) — уникальный идентификатор версии
- **sheet_id** (FK) — ссылка на лист
- **created_by_user_id** (FK) — пользователь, сохранивший версию
- version_name — название версии
- layout_json — сохранённая конфигурация расположения модулей
- created_at — дата создания версии
## **4. ModuleDefinition (Определение модуля)**

- **module_def_id** (PK) — уникальный идентификатор типа модуля
- **created_by_user_id** (FK) — пользователь-создатель (NULL для системных модулей)
- name — название модуля
- module_type — тип модуля (text, roll, custom)
- config_schema_json — схема структуры модуля
- default_width — ширина по умолчанию
- default_height — высота по умолчанию
- is_system — признак системного модуля
- created_at — дата создания
## **5. CustomModuleField (Поле пользовательского модуля)**

- **field_id** (PK) — уникальный идентификатор поля
- **module_def_id** (FK) — ссылка на определение пользовательского модуля
- field_name — название поля
- field_type — тип поля (text, number, checkbox, image и др.)
- default_value — значение по умолчанию
- position — порядок отображения в модуле
## **6. SheetModuleInstance (Экземпляр модуля на листе)**

- **module_instance_id** (PK) — уникальный идентификатор экземпляра
- **sheet_id** (FK) — ссылка на лист
- **module_def_id** (FK) — ссылка на тип модуля
- **snap_group_id** (FK) — ссылка на группу стыковки (если модуль соединён с другими)
- position_x — координата X размещения
- position_y — координата Y размещения
- width — ширина модуля
- height — высота модуля
- z_index — порядок наложения
- custom_config_json — данные конкретного модуля
- created_at — дата добавления
## **7. SnapGroup (Группа стыковки модулей)**

- **snap_group_id** (PK) — уникальный идентификатор группы
- **sheet_id** (FK) — ссылка на лист
## **8. TextModuleData (Текстовый модуль)**

- **module_instance_id** (PK, FK) — ссылка на экземпляр модуля
- text_content — текстовое содержимое
- image_url — ссылка на изображение
- font_size — размер шрифта
- text_align — выравнивание текста
## **9. RollModuleData (Модуль роллов)**

- **module_instance_id** (PK, FK) — ссылка на экземпляр модуля
- dice_formula — формула броска (например, 1d20+5)
- modifier — числовой модификатор
- last_result — последний результат броска
## **10. RollHistory (История бросков)**

- **roll_id** (PK) — уникальный идентификатор записи
- **module_instance_id** (FK) — ссылка на модуль роллов
- result_value — полученный результат
- formula — использованная формула
- rolled_at — дата и время броска


### **Связи между сущностями**

|Связь|Тип|Описание|
|---|---|---|
|**User – Sheet**|1:N|Один пользователь может создать несколько листов персонажей. Каждый лист принадлежит одному пользователю.|
|**User – ModuleDefinition**|1:N|Один пользователь может создать несколько пользовательских модулей. Каждый пользовательский модуль создаётся одним пользователем.|
|**Sheet – SheetModuleInstance**|1:N|Один лист содержит множество модулей. Каждый модуль размещается только на одном листе.|
|**Sheet – SheetVersion**|1:N|Один лист может иметь несколько сохранённых версий конфигурации. Каждая версия относится к одному листу.|
|**Sheet – SnapGroup**|1:N|Один лист может содержать несколько групп стыковки модулей. Каждая группа относится к одному листу.|
|**ModuleDefinition – SheetModuleInstance**|1:N|Один тип модуля может использоваться в нескольких экземплярах на разных листах. Каждый экземпляр создаётся на основе одного типа модуля.|
|**ModuleDefinition – CustomModuleField**|1:N|Один пользовательский модуль может включать несколько настраиваемых полей. Каждое поле принадлежит одному модулю.|
|**SnapGroup – SheetModuleInstance**|1:N|Одна группа стыковки объединяет несколько модулей. Каждый модуль может входить только в одну группу или не входить ни в одну.|
|**SheetModuleInstance – TextModuleData**|1:1|Экземпляр текстового модуля имеет одну запись текстовых данных. Эти данные относятся только к данному модулю.|
|**SheetModuleInstance – RollModuleData**|1:1|Экземпляр модуля роллов имеет одну запись параметров броска. Эти данные относятся только к данному модулю.|
|**RollModuleData – RollHistory**|1:N|Один модуль роллов может иметь несколько записей истории бросков. Каждая запись относится к одному модулю.|

### **Общая информация**
**Проект:** Создатель/редактор чарлистов для НРИ DEMICHAR  
**Основная задача:** Создание и редактирование листов персонажей для настолько-ролевых игр, обеспечение навигации по ключевым разделам.
Страницы построены по модульному принципу и содержит следующие функциональные зоны (блоки):



### **Структура и функциональность страниц**

### Страница №1: Авторизация
Обязательна для авторизации пользователя в системе.

- Логотип / Название: DEMICHAR - некликабельный элемент
- Описание: Некликабельный элемент с описанием сайта
- Вход - кнопка, ведущая на страницу входа (такой  страницы пока нет, поэтому она сразу ведет на Страницу №2)
- Регистрация - кнопка, ведущая на страницу регистрации (страницы регистрации пока нет и кнопка ничего не делает)

### Страница №2: Главная
Главная страница с выбором уже созданных персонажей, а также созданием новых и переходом на страницу профиля.

- Логотип / Название: DEMICHAR - некликабельный элемент.
- Зеленый шар - Логотип (еще не придумали)
- Красный шар - на его месте будет отображаться аватар вошедшего пользователя
- Кнопки:
	- "Профиль" - (предполагаемо) переход в профиль вошедшего пользователя;
	- Поле с уже созданным персонажем - открытие файла персонажа с переходом на Страницу №3;
	- Кнопка "+" - создание пустого листа;
	- Троеточие у созданного персонажа - (предполагаемо) раскрывание маленького окна, в котором будет выбор среди кнопок:
		- Скачать json - скачивание файла персонажа;
		- Дублировать - дублирование персонажа.

### Страница №3: Лист персонажа
Страница с листом персонажа, в которой по нажатию

- Логотип / Название: DEMICHAR - кликабельный элемент, переносит на главную Страницу №2.
- Зеленый шар - Логотип (еще не придумали)
- Красный шар - на его месте будет отображаться аватар вошедшего пользователя
- Интерактивные элементы:
	- "Профиль" - (предполагаемо) кликабельный элемент, переход в профиль вошедшего пользователя;
	- Аватар персонажа - (предполагаемо) кликабельный элемент с помощью которого можно сменить аватар своему персонажу;
	- Имя персонажа (по умолчанию "Безыменный персонаж") - (предполагаемо) кликабельный элемент, можно сменить имя;
	- Фиолетовая кнопка с кубом D20 - (предполагаемо) кликабельный элемент, раскрывает окно с выбором кубов (d2, d4, d6, d10, d12, d20 и d100)
	- "Модули" - кликабельный элемент, переносит страницу в самый низ для выбора модулей из готовой библиотеки
